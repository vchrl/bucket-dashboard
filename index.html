1. Overview

What counts as TVL

Total TVL = V2 collateral + Farm deposits + V1 collateral − BUCK held in V2's PSM. Farm deposits are gross (idle pool balances plus positions deployed into Navi and Scallop strategies), per the protocol's definition. PSM BUCK is virtual liquidity provisioned for DEX routing and is netted to avoid counting V1-minted BUCK on both sides. Collateral valued at Bucket's own on-chain oracle where it publishes, DEX VWAP otherwise; thin assets shown at token count and flagged.

2. Bucket V2: collateral vaults

How a vault is measured

Each vault's TVL is its on-chain total_coll_amount, split into idle (held in the vault) and deployed (routed into farm strategies, tracked in the vault's own ledger). The identity idle + deployed − total = 0 is verified on every refresh for all vaults. A failed check surfaces in section 6 instead of silently shipping a wrong number.

3. Bucket Farm: deposit pools

How the Farm is measured

Farm TVL is gross deposits per the protocol's definition: each pool's idle balance plus positions deployed into external strategies (Navi, Scallop), read from the pool's own ledger. Deployed positions carry borrowing on the destination protocols that this gross figure does not net; the split is shown per pool. Pools with no on-chain write in a period carry their last verified state forward, with age shown. Never silently dropped, never silently zeroed.

4. Bucket V1: legacy CDP

How V1 is measured

V1 is winding down but not frozen: positions still close every month. Its series is rebuilt from position-level events (each carrying full collateral and debt state), so it reflects real closures rather than a carried-forward snapshot. The staking fountain is excluded by construction. It registers debt, not collateral, and its collateral never leaves the core protocol.

5. USDB: supply & backing (Scope 2)

Where USDB comes from

USDB enters supply through multiple doors: user borrowing against collateral, PSM swaps, and protocol-side mints. This section decomposes outstanding supply by mint origin so the borrowed share is visible next to the total. Supply is a liability, not TVL, and the two are never conflated on this page.

6. Data integrity: live checks

Why this section exists

A dashboard asserting a number without showing its derivation is exactly as unfalsifiable as the number it replaces. Every refresh re-runs these checks against on-chain state. A failing check renders here in red before any headline updates. The failure mode is loud, never a silently wrong total.
